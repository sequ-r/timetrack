# timetrack

A GNOME time tracking application written in Rust with GTK4 and libadwaita.

Timetrack is an early-stage project. The current UI is the application
scaffold; the time tracking functionality itself is not implemented yet.

## Building

The project is a Rust crate driven by Meson. Meson handles resource
compilation, gettext, and packaging, and invokes `cargo build` for the
actual compilation. The GTK4 and libadwaita development files must be
installed.

```sh
# Fedora
dnf install gtk4-devel libadwaita-devel

# Debian/Ubuntu
apt install libgtk-4-dev libadwaita-1-dev
```

Build and install to a local prefix. No root is required if you install
under your home directory:

```sh
meson setup builddir --prefix="$HOME/.local"
meson compile -C builddir
meson install -C builddir
```

Use `--prefix=/usr` instead if you want a system-wide install; that one
needs root.

Note that `src/config.rs` is generated by Meson and is tracked in git
precisely so that a fresh clone compiles with plain `cargo build`. Meson
writes it back into the source tree, so running `meson setup` with a
different prefix will show up as a modification to `src/config.rs` in
`git status` — that is expected, and `git checkout src/config.rs` restores
the committed values.

## Running

The app must be **installed** before it will start, not just compiled.
`main.rs` loads its GResource bundle from the install prefix
(`$PKGDATADIR/timetrack.gresource`) and aborts if it is missing, so running
the binary straight out of `builddir/src/` will fail with:

```
Could not load resources: Failed to open file ".../timetrack.gresource"
```

After `meson install`, run the installed binary:

```sh
~/.local/bin/timetrack
```

If your session does not pick up the icons and GSettings schema
automatically, point them at the install prefix:

```sh
GSETTINGS_SCHEMA_DIR="$HOME/.local/share/glib-2.0/schemas" \
XDG_DATA_DIRS="$HOME/.local/share:${XDG_DATA_DIRS:-/usr/local/share:/usr/share}" \
~/.local/bin/timetrack
```

If the window does not appear, check that it is not already running as a
background instance — the app is single-instance, so activating the desktop
entry again just raises the existing window:

```sh
pkill timetrack
```

### What to check

The window opens on the application scaffold — the tracked "Hello, World!"
label is still the only content. The parts worth a look are the ones this
project's fixes touched:

- **Open the hamburger menu** (top right). Preferences, Keyboard Shortcuts
  and About should all be present and respond. Preferences and Keyboard
  Shortcuts were previously registered in the menu but wired to no handler,
  so they did nothing at all.
- **Keyboard Shortcuts** should open a real shortcuts window listing Quit
  and Show Shortcuts. If instead you get a dialog saying it requires
  libadwaita 1.7 or newer, your system is too old for `AdwShortcutsDialog`
  — the app degrades rather than crashing, but the shortcut window is
  unavailable.
- **About** should show an Adw about dialog with the translator credits
  field.
- The window should size itself to roughly 800x600 and follow the light or
  dark theme of your session.

Nothing here is styled or polished yet; that is expected at this stage.

## Tests

Run the test suite (validates the desktop file, GSettings schema, and
AppStream metadata):

```sh
meson test -C builddir
```

There is no unit test suite yet; the Meson tests are metadata validation
only.

## Flatpak

`org.sequ.timetrack.json` builds the app as a Flatpak against the GNOME 50
platform:

```sh
flatpak-builder --user --install build-dir org.sequ.timetrack.json
```

The manifest fetches its source from GitHub, so it builds the pushed state
of `main` rather than your working tree. To build what you currently have
checked out, point the builder at the local directory instead:

```sh
flatpak-builder --user --install build-dir . timetrack
```

## Requirements

- GTK 4.7 or newer
- libadwaita 1.7 or newer — `AdwShortcutsDialog` is used by the keyboard
  shortcuts window and does not exist in earlier versions
- Rust 2021 edition
