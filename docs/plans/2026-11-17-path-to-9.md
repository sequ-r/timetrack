# The path to 9/10

Written 2026-11-17 against `main` at `1186a11`. Produced by five independent
reviewers working from one brief, each with a different model, converging over
three voting rounds. All five signed the plan; their amendments are folded in.

This is a plan for the author to execute, not a decision record. Where it makes
a product choice, the choice is named and belongs to the author.

## 2. What stands between here and 9

Everything below was confirmed by reading the tree at `1186a11`, not taken from
the docs; no item depends on running the app. The one claim left unverified is
the Windows named pipe's DACL permissiveness — the machine-wide name and the
unbounded timeout are in the code, the default access control is not. The plan
is built from these, in this order of severity.

1. **A live credential leak.** `resolve_against` returns an absolute redirect
   `Location` verbatim ([caldav.rs:155](../../crates/timetrack-service/src/caldav.rs#L155)),
   the redirect loop re-attaches Basic auth on the next hop
   ([caldav.rs:423](../../crates/timetrack-service/src/caldav.rs#L423)), and
   `origin_of` accepts plain `http`
   ([caldav.rs:176](../../crates/timetrack-service/src/caldav.rs#L176)). A hostile
   calendar, or an open redirect on a real one, captures the stored password.
2. **An endpoint that is not actually per-user, bounded, or exclusive.** On
   Windows `socket_path_from` keys on `HOME`
   ([socket.rs:81](../../crates/timetrack-proto/src/socket.rs#L81)), which is normally
   unset there, so every account derives `<temp>/timetrack-user.sock` and
   `pipe_name_of` keeps only the file name
   ([socket.rs:537](../../crates/timetrack-proto/src/socket.rs#L537)). `connect` ignores
   its timeout ([socket.rs:476](../../crates/timetrack-proto/src/socket.rs#L476)) and
   `set_read_timeout` is a no-op off Unix
   ([socket.rs:549](../../crates/timetrack-proto/src/socket.rs#L549)), though
   `CALL_TIMEOUT` promises ten seconds. Single instance is probe → remove → bind
   ([service/socket.rs:220](../../crates/timetrack-service/src/socket.rs#L220)), so two
   racing starts can unlink a live listener and run a second service over its own
   whole-store mirror.
3. **Cost proportional to lifetime history.** `recent()` never limits
   ([model.rs:138](../../crates/timetrack-core/src/model.rs#L138)), so every snapshot
   serializes every entry; the GUI polls every 30 s
   ([app.rs:68](../../crates/timetrack-gui/src/app.rs#L68)); and every mutation clones
   the whole store and diffs every entry
   ([interface.rs:310](../../crates/timetrack-service/src/interface.rs#L310)). A
   ten-year ledger is ~5.5 MB of JSON per poll.
4. **A map that lies in places.** `interface.rs:8` still calls itself "The D-Bus
   interface implementation"; `service/socket.rs:10` says "dual-served beside
   D-Bus"; `proto/Cargo.toml:8` advertises a "Shared D-Bus contract". §15 claims
   172 core tests where the tree has 201
   ([REQUIREMENTS.md:540](../../REQUIREMENTS.md#L540)), and "no known defects"
   ([REQUIREMENTS.md:606](../../REQUIREMENTS.md#L606)) while the README lists four
   ([README.md:435](../../README.md#L435)). `ClientError::VersionMismatch`
   ([lib.rs:355](../../crates/timetrack-proto/src/lib.rs#L355)) is never constructed, so
   the GUI footer and all three tray backends' skew branches are unreachable;
   `no_running_state_survives_anywhere`
   ([app.rs:2262](../../crates/timetrack-gui/src/app.rs#L2262)) loops over an empty
   `Vec`; `JsonStore::save`
   ([storage.rs:410](../../crates/timetrack-core/src/storage.rs#L410)) has no
   production caller.
5. **Verification that stops at Linux's edge.** Installers are checked only by
   Linux-side static checks, `gui-native` is explicitly non-blocking
   ([ci.yml:244](../../.github/workflows/ci.yml#L244)), and `gui-smoke.sh` exits 0 when
   it skips ([gui-smoke.sh:851](../../scripts/gui-smoke.sh#L851)).
6. **Four modules that hold whole subsystems** — `interface.rs` 3,266 lines,
   `gui/src/app.rs` 2,796, `cli/src/main.rs` 2,699, `store/src/lib.rs` 2,429 —
   and GUI render modules at 0% line coverage because only pixels exercise them.

## 3. What a 9 means here

A 9 is not "more features". Nothing in the plan adds product surface. A 9 is:

- **trusting the two boundaries the design admits** — the socket, and the one
  network egress that carries a password;
- **a data path whose cost tracks the change**, which is the claim §17 makes for
  SQLite and the code has not yet earned;
- **documents that are true**, because this repository's documentation is how
  every agent and contributor navigates it;
- **checks that have been seen to fail**, on the platforms the app ships to;
- **modules a newcomer can enter** without scrolling 2,000 lines.

## 4. The plan

Order is deliberate: two small, confirmed security fixes first so nothing is
built on top of them; then the one large architectural change; then the truth
pass that must document the final shape; then structure and gates.

Every workstream is a series of small PRs against `main`, each green under the
existing gates. Definitions of done are checks that can fail — not descriptions.

### WS1 — Close the external-source credential boundary

**Size S · Risk low · First.**

Scope every new refusal to requests that actually carry `Authorization`: a
cross-origin redirect of an authenticated request is dropped and refused with
the redirected host named (an authenticated cross-host redirect is not a
legitimate CalDAV flow); https→http downgrade refused; `http` allowed only to
loopback. An unauthenticated CalDAV fetch or `.ics` feed keeps today's
behaviour — `fetch_source_texts`
([interface.rs:1184](../../crates/timetrack-service/src/interface.rs#L1184)) sends no
credentials, so public feeds are unaffected.

**Done when** three tests in the existing CalDAV local-server rig fail on
today's code and pass after: an authenticated cross-origin redirect carries no
`Authorization` and is refused; a downgrade is refused; a non-loopback `http`
endpoint is refused at registration.

### WS2 — Own the local endpoint: per-user, bounded, exclusive

**Size M · Risk medium · Second.** Three PRs, in this order.

1. Derive the path from a per-user identity (uid / SID) rather than a home
directory name; put that identity in the Windows pipe name and set an
owner-only DACL.
2. Enforce `CALL_TIMEOUT` at connect and per frame-read on every platform,
deleting the no-op.
3. Claim the endpoint atomically under a lock held for the process lifetime
(`flock` / `LockFileEx`), unlinking a stale socket only while holding it.

**Done when** a concurrent-start test (8 racers at one path) yields exactly one
`Listening` and never unlinks a live socket; a wedged-peer test fails within
`CALL_TIMEOUT` on Linux, Windows and macOS; name derivation has unit tests in
the `cross` job.

### WS3 — Make cost proportional to the change

**Size L · Risk high · Third.** Two PR streams sharing one design; `interface.rs`
and `store/lib.rs` are touched here and not again in WS5.

**3a — windowed, revisioned wire.** `Request::Snapshot` gains `since`;
`Snapshot` carries a bounded `entries` window, `total_entries` and a `revision`;
`Changed` carries the revision. `revision` is persisted in the store's `meta`
table and bumped inside the same transaction as the mutation, so a restart
cannot answer `since` with an empty delta; a client whose `since` exceeds the
service's revision (a restored backup) gets a full snapshot. Bump
`SOCKET_API_VERSION` to 2 and **construct** `VersionMismatch` on disagreement,
which makes the skew UI in the GUI and tray reachable instead of dead.
`list --search` and range export become server-side paged requests, reusing the
core's scope predicates rather than new SQL ones (§14/#131 wording updated in
4b; the e2e search checks must stay green). The GUI needs "load older" paging
so entries outside the window remain reachable and editable — no silent
truncation. Window bounds come from the core's DST-aware `Tz::day_start`
([tz.rs:216](../../crates/timetrack-core/src/tz.rs#L216)), never a naive UTC week start,
with a transition-week test. Totals stay in the core, per-instant, DST-correct;
ADR 0021 records per-poll totals as deliberately O(history) in Rust until a
measurement says otherwise.

**3b — mutation without the whole-store clone.** Apply the rule to the records
it touches, build the journal from those ids, and on persist failure restore the
pre-images in memory — the SQLite write is already one transaction, so the
invariant is "memory always equals disk". Split `service/src/interface.rs` and
`store/src/lib.rs` along the seams this creates (state/mutate, entries,
projects, sources+suggestions, caldav state, tombstones) as part of the same PR
stream.

**Done when** with 20,000 seeded entries a snapshot frame stays ≤256 KiB and
`entries.len() ≤ 200`; a quick-add's changed rows are ≤3; bytes cloned or
wall-time at 20k entries is within a small constant of a 100-entry store (a
check that fails if the clone survives); `scripts/e2e.sh` passes unchanged; a
skew test drives `VersionMismatch` through the GUI and tray status paths.

### WS4 — Truth pass

**Size S · Risk none · 4a immediately, 4b after WS3.**

**4a, independent of everything else.** Rewrite the module headers and crate
descriptions that still describe the retired D-Bus service (`interface.rs:8`,
`service/socket.rs:10`, `proto/Cargo.toml:8`, `gui/app/service.rs:9`); CLI help
"Start of the interval" → "entry" ([main.rs:88](../../crates/timetrack-cli/src/main.rs#L88)),
per GLOSSARY; replace the vacuous §7 guard with an assertion that can fail; gate
`JsonStore::save/append` behind test support, keeping `load` for the legacy
import; replace `applies: bool` with an `UpdateChannel` so an installed
Windows/macOS build says "update from the release page" instead of "this is a
host build" ([update.rs:83](../../crates/timetrack-gui/src/app/update.rs#L83)).

**4b, after WS3.** Reconcile §14's `store.json` backup sentence
([REQUIREMENTS.md:508](../../REQUIREMENTS.md#L508)) with §17's db + `-wal` rule;
generate §15's counts from `cargo test -- --list` instead of typing them;
reconcile "no known defects" with the README's four; add the snapshot-window
ADR; amend ADR 0020 to "model ready, sync out of scope"; record the §14/#131
search-wording change; and, if WS6's coverage floor becomes blocking, record
that #111's decision was reopened.

**Done when** `scripts/check-docs.sh` fails on reintroduction of the retired
phrases and on a §15 count that disagrees with the tree.

### WS5 — Split by seam, and make the GUI testable

**Size M/L · Risk medium · After WS3.** CLI and GUI only — the service and store
splits belong to WS3b. One crate per PR; behaviour-preserving except the render
extraction.

- `cli/src/main.rs` → one module per command group, clap structs untouched.
- `gui/src/app.rs` → `TimetrackView`'s 31 fields decomposed into per-feature
  state objects (dialogs, prompts, export, update, IME), with pure render-state
  functions (rows, values, widths, labels) extracted out of `render/` so they
  are unit-testable.
- A CI ratchet fails any production file over 900 lines. It counts non-test
  lines (or `rules.rs`, 785 production against 1,680 total, would trip
  spuriously), gates only the files a PR touches, and its exception list shrinks
  by one file per decomposition PR — not by every PR, so a small fix is never
  forced to decompose an unrelated file.

**Done when** the ratchet fails on a 901-line production file; the workspace test
count has not gone down; GUI line coverage rises from 40.9% to at least 55%,
earned by render-state tests rather than by the pixel rig.

### WS6 — Gates that fail, and one native surface

**Size M · Risk flake on the pixel rig only · Last.**

- `gui-native` upgraded from liveness to functional (install/launch → quick-add
  → status → undo → restart persistence) and made a required check in the branch
  ruleset; an e2e subset runs natively on Windows and macOS.
- `gui-smoke.sh` exits non-zero when a driver is missing; `TT_ALLOW_SKIP=1` for
  local development only.
- `cargo-deny` for advisories and licences, with the workspace's no-tokio rule
  made mechanical.
- A coverage floor at today's 63.9%, that only ratchets upward, pinned to a
  fixed toolchain and bumped in the PR that moves the toolchain. It reopens
  [#111](https://github.com/sequ-r/timetrack/issues/111) explicitly; if that
  decision is not reopened, the floor ratchets but stays informational.
- One dispatch test per CLI subcommand.
- **One native surface, chosen at kickoff — not both:** either (a) the existing
  tray backends (`backend_windows.rs`, 1,148 lines; `backend_macos.rs`, 796)
  exercised and working on real Windows/macOS, with a dated §15 record, or
  (b) installer-channel self-update shipped for one of those platforms. Plus one
  install → upgrade → uninstall walkthrough performed on real hardware and
  recorded with a date in §15, whichever surface is chosen.

**Done when** every gate has been shown red on a seeded failure in its own PR;
a one-point coverage drop fails; `cargo deny check bans` fails if tokio enters
the graph; §15 carries a dated record naming the platform and the surface.

## 5. Not in this plan

- **Sync (§20 / ADR 0020).** A product feature with no consumer. The ADR is
  amended to say so; the model gaps (source UUIDs, removal tombstones, external
  UID) are closed in the slice that needs them, not before.
- **Provider-specific calendar APIs.** Already declined (ADR 0019).
- **Native save dialogs and a tray rewrite per OS**, beyond the one surface WS6
  names. L-sized, needs hardware, extends surface rather than extendability.
- **A fuzzing campaign.** Bounded round-trip property tests land only where WS3
  touches serialization.
- **A TUI, i18n, telemetry, a GUI source editor.** Product surface, not distance.

The pixel rig stays the authority for painting; the render extraction in WS5
supplements it rather than replacing it.

## 6. Score after landing

WS1–4 fix the confirmed defects and land the project at about **8.5**. That is
the ceiling every one of the five raters put on the plan once the native surface
was excluded — not a number this document chose.

WS5 and WS6 are what make **9** credible: the GUI becomes verifiable without
pixels, the ledger matches the tree, and the platforms the app ships to are
proven by something other than Linux running static checks. **If the native
surface in WS6 slips, the honest ceiling is 8.75** — and the document should
say 8.75, not 9.

## 7. Starting

1. WS1 as a single PR — it is small, it fails closed, and it is the only
   confirmed leak.
2. WS2's three PRs, in order: identity, timeouts, ownership.
3. WS3a behind a version bump, keeping the full-snapshot fallback so a client
   and service of different builds refuse rather than misread.

A workable issue split is one issue per workstream with the sub-steps as a
checklist, so each PR closes a line on it. `REQUIREMENTS.md` §15 is the ledger to
update as each row lands; this document is the plan, not the record.
