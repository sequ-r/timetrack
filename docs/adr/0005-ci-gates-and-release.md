# CI is the only gate, and the release calls it

`.github/workflows/ci.yml` is the only definition of a green tree -- rustfmt, clippy, `cargo test --workspace`, `scripts/e2e.sh` against a real service, and `scripts/gui-smoke.sh` driving the GUI on a headless X server -- and it runs on every pull request and on `main`, one job per check so a red run names the check that failed. `main` requires those five checks before a pull request can merge (an owner can still push past them: `enforce_admins` is off). `release.yml` calls the same workflow as a reusable one, so the AppImage builds and publishes only on a commit those jobs pass; `workflow_dispatch` on it is a dry run (build and verify, publish nothing, keep the artifacts) because the packaging path has to be checkable without cutting a version.

Exactly one job publishes, and it waits for the build. Two publishers each generate the release notes and each write their own `SHA256SUMS`, which is how v0.1.0 shipped notes printed twice and a checksum file naming one of the two tarballs; the publish job downloads the build, writes one `SHA256SUMS` over every file, and is the only caller of the release action. Both workflows get their system packages from `.github/actions/setup`, so the list gpui needs lives in one place rather than in every job.

Since 0007, runs mint their own version per run and the tag trigger is gone: pushing to `main` releases, and a manual `v*` tag push releases nothing. Since the trigger was limited to app paths, only pushes touching the app release; anything else runs `ci.yml` but mints no version.
