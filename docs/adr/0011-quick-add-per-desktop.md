# Quick-add per desktop: tray where watchers live, launcher actions on GNOME

The tray is a headline quick-add surface, but stock GNOME — the stated target desktop — has no StatusNotifier watcher for it to appear in, and the AppImage (the install, ADR 0008) did not bundle it, so the default install on the default desktop had no tray and said nothing about it. Quick-add is now explicitly per-desktop. On watcher desktops (KDE, XFCE, MATE, GNOME with a tray extension) the tray ships **inside the AppImage** (`TimeTrack-*.AppImage tray`, or a `timetrack-tray` symlink to the image, mirroring the CLI dispatch); the tray code otherwise stays as it is. On stock GNOME the quick-add path is the launcher itself: the desktop entry gains `+5/+15/+30/+60` actions (right-click in the dash or app grid) that run the bundled CLI's `quick` against the first active Project and confirm through a desktop notification (`timetrack quick --notify`), alongside the GUI Home tab's quick-add keys and a user-bound custom keyboard shortcut to the same CLI command. A tray that finds no watcher is no longer a silent dead surface: it logs and posts one desktop notification saying the tray cannot appear here and naming those alternatives, then keeps waiting in case a watcher appears.

## Considered Options

- **GNOME Shell extension.** Rejected: a second artifact in a second language with its own store review and a compatibility treadmill per Shell release, to replicate a menu the launcher actions already approximate — and nothing else in the project needs that maintenance surface.
- **GlobalShortcuts portal.** Rejected for now: bindings live only while the requesting process (the GUI) runs, first use needs a system approval dialog whose behaviour varies by portal backend, and quick-add would still need a chosen Project and bucket per binding. A custom shortcut the user binds to the documented CLI command gets the same keystroke today with no session lifetime at all; the portal can be revisited if that proves too manual.
- **Bundle the tray and call it done.** Rejected as the whole answer: it fixes KDE-family AppImage users, but on stock GNOME the bundled tray is exactly as invisible as the host one was — bundling without the GNOME path and the watcherless notice would just ship the dead surface to more people.
